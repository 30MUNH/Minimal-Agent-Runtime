System Architecture

The Minimal Agent Runtime is organized into modular, loosely-coupled components designed for predictability, sandboxing, and testability.

Core Architecture Pipeline

1. Agent Runtime Loop

The central orchestrator maintains an execution loop up to max_steps. Each iteration passes the accumulated working transcript and tool schemas to the model provider.

2. Model Provider Interface

Abstracted via Python Protocol. Receives messages and schemas, returning a normalized ModelReply (either final answer or structured tool_call).

3. Tool Registry & Dispatch

A name-indexed dictionary of Tool instances. Validates arguments against JSON schemas and executes handlers without model-specific code branches.

4. Observations & Recovery

Tool results or caught exceptions are formatted as structured observations (`tool_result` / `tool_error`) and fed back into the transcript for model recovery.

Memory Architecture

Working Memory (Ephemeral)

The active message transcript maintained during a single run() call. Stores user prompt, model completions, tool calls, and observations. Discarded upon task completion.

Persistent Memory (Cross-Run)

Backed by JsonMemory storing key-value pairs in .agent-memory.json. Explicitly accessed via remember(key, value) and recall(key) tools, surviving process restarts.

Observability & Tracing

Execution Trace

Chronological step-by-step array tracking model invocations, tool requests, tool status, execution duration in milliseconds, and final termination reason.

JSON Run Logs

Structured audit logs written to logs/run-XXX.json containing complete execution metadata, timing stats, tool usage counts, and answers without leaking secrets.
